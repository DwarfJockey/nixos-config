# Desktop session

**Desktop stack:** [Umbriel](https://github.com/noctalia-dev/umbriel) (scrollable-tiling Wayland compositor, C++23 on wlroots 0.20 + SceneFX, by the Noctalia authors) + Noctalia (bar/dock/control-center/lock), driven from keybinds with `noctalia msg <cmd>`. Noctalia detects Umbriel via `UMBRIEL_SOCKET` and has a dedicated workspace/keyboard backend for it — but only since noctalia `21a272f` (2026-08-19); older pins fall through to the generic `ext-workspace-v1` backend, which carries no occupancy bit, so every workspace reads as empty and the bar's `occupied_color` never renders. Noctalia runs as a `systemd.user.services.noctalia` unit bound to `graphical-session.target` with a short `TimeoutStopSec` (it ignores SIGTERM, so as a compositor-spawned scope it stalled shutdown for the full 90s stop timeout). Mod is Super; navigation is arrows, not hjkl. Umbriel is young and its config keys are explicitly not stability promises — check upstream `docs/user/` before assuming a key still exists.

Umbriel supplies natively what niri needed workarounds for: blur (`appearance.blur` + a `[[layer_rule]]`), `corner_radius`, and a drop shadow. It brings no polkit agent, and neither does Noctalia: `fprintd-enroll`/`pkexec` get an instant, promptless `PermissionDenied`, with zero polkit activity in Noctalia's logs and no agent owner in `busctl --user list`. So `modules/desktop/polkit.nix` runs a `systemd.user.services.polkit-agent` (mate-polkit) instead. It's GTK, not Qt, specifically to avoid the Kvantum/`QT_STYLE_OVERRIDE` segfault that killed niri-flake's `polkit-kde-agent` (Stylix's qt target exports `QT_STYLE_OVERRIDE=kvantum`, which a Qt/QML agent chokes on). Screen capture goes through `xdg-desktop-portal-umbriel` (`modules/desktop/umbriel.nix`); the `.portal` file matches on `XDG_CURRENT_DESKTOP=umbriel`, which the compositor exports lowercase. Touchpads are the exception to "Umbriel supplies it natively": it applies only `tap` and `natural_scroll` and never calls `libinput_device_config_click_set_method()`, so the clickpad takes libinput's default button-areas. `modules/desktop/touchpad.nix` therefore ships an `/etc/libinput/local-overrides.quirks` entry that borrows `ModelChromebook` for its click-method side effect to get clickfinger (1/2/3-finger press = left/right/middle). It is a model label, not a click-method knob — delete it if Umbriel ever gains a `click_method` key. XWayland goes through the xwayland-satellite on the Umbriel package's wrapper PATH; the NixOS half of `desktop/umbriel.nix` overrides `programs.umbriel.package` to patch it (clamp negative `WM_NORMAL_HINTS` sizes — mono WinForms sets them, and the resulting protocol error panics satellite and drops every X client), and its Home Manager half takes `osConfig.programs.umbriel.package` so there is one umbriel. `corner_radius` is the other exception: Umbriel rounds per scene buffer and only the toplevel's own surface, so a client that paints into a `wl_subsurface` — Gecko, hence Zen — keeps square corners inside the rounded border ring (detail in `agent_docs/theming.md`).

**Session autostart:** Umbriel raises `umbriel-session.target` (→ `graphical-session.target`) with `--no-block` and then immediately spawns `general.autostart`, so an autostart entry can never be ordered after a session service. **Tray apps therefore must be `systemd.user.services` with `After = [ "noctalia.service" ]`, never `general.autostart`** — built by `modules/_lib/tray-app.nix`, one per app file. Noctalia hosts `org.kde.StatusNotifierWatcher` but only claims the name seconds into startup, and Electron asks `NameHasOwner` exactly once at tray-creation with no Wayland fallback and no retry — so 1Password and Vesktop used to come up running but permanently invisible (hidden by `--silent`/`--start-minimized`, no icon to restore from). `noctalia.service` is `Type = "dbus"` on that name so the unit only goes active once the watcher is live, which is what makes the `After=` meaningful. Apps that re-register on `NameOwnerChanged` (Steam, via libayatana-appindicator) can stay in `general.autostart`. Zen needs no tray but is a unit anyway: autostart children share `umbriel.service`'s cgroup, so at logout Zen and the compositor get SIGTERM together and Zen dies mid-shutdown without a display (and `umbriel.service` hung its full stop timeout). As a unit it is stopped before the compositor.

**Login:** `greetd` runs **Noctalia Greeter** (`modules/desktop/greeter.nix`), which brings its own wlroots compositor and matches the Noctalia shell. There is deliberately **no autologin** — that file only sets `services.greetd.enable` and configures the greeter; the greeter module owns `default_session.command`, and nixpkgs defaults `default_session.user` to `greeter`. Do not set either: the greeter module reads `default_session.user` to own `/var/lib/noctalia-greeter`, and adding an `initial_session` would both bypass the greeter and make logind register the desktop as `Class=greeter` (which breaks `Lock`/`SetLockedHint`, so the compositor and Noctalia log "Session does not support lock screen"). The greeter is **password-only**; sessions are discovered from `wayland-sessions` `.desktop` files via `XDG_DATA_DIRS`, and `settings.session.default` takes the picker *label* (`Umbriel`), not the `.desktop` id — list them with `noctalia-greeter sessions`. The entry itself comes from `programs.umbriel`, whose NixOS module registers the package in `services.displayManager.sessionPackages`.

**Fingerprint:** `services.fprintd.enable` makes nixpkgs default `security.pam.services.<name>.fprintAuth` to true for **every** PAM service, putting `pam_fprintd` first as `auth sufficient`. PAM auth is serialised, so any graphical caller that cannot render "place your finger" blocks for its full 30s timeout before `pam_unix` sees the typed password. `modules/desktop/fingerprint.nix` therefore keeps it for `sudo` but sets `login.fprintAuth = false` — the stack Noctalia's lock screen uses. Noctalia runs its own fprintd client alongside PAM, so swipe-to-unlock still works there. Enroll with `fprintd-enroll -f <finger>` as the user (**not** under `sudo`, which enrolls root); prints live in `/var/lib/fprint`, which is persisted.

`desktop/fingerprint.nix` must stay even on hardware without a reader (set its two `true`s to `false` instead) — `nixos-hardware`'s framework module sets `services.fprintd.enable = lib.mkDefault true`, so deleting the file would leave fprintd enabled *and* lose the `login.fprintAuth = false` fix. The file sets plain values, which outrank that `mkDefault`.

**Wallpaper:** A source photo is vendored at `modules/_lib/wallpapers/acrylic-pour-magenta-cyan.jpg`, remapped onto the base16 palette (lutgen, luminosity-preserved) and dimmed toward `base00` (imagemagick) into `themedWallpaper` — a PNG built in the Nix store, so it tracks the scheme and survives the ephemeral root. The derivation lives in `modules/_lib/wallpaper.nix` because both the Noctalia shell (Home Manager) and the greeter (NixOS) show it and the greeter cannot reach into Home Manager scope; identical arguments mean one build and one store path. Noctalia ignores `settings.wallpaper.default.path` (its *live* wallpaper lives in non-persisted runtime state, seeded from its bundled default — see *Noctalia settings* below), so it is not set; instead `noctalia msg wallpaper-set` applies `themedWallpaper` from `hooks.started` at every Noctalia start and from a `home.activation.noctaliaWallpaper` hook after each switch (`modules/desktop/noctalia.nix`). Cycling is disabled.

**Umbriel config generation:** `programs.umbriel.settings` (`modules/desktop/umbriel.nix`) is a **free-form attrset**, not a typed module — it goes straight through `pkgs.formats.toml` to `~/.config/umbriel/config.toml`, so any key the binary supports can just be written. There is no raw-config escape hatch and none is needed. `programs.umbriel.validateConfig` (on by default) runs `umbriel validate -c` on the result at build time, so an unknown or malformed key fails the rebuild rather than the login. Umbriel also live-reloads the file on save, but here it is a store symlink, so a rebuild is what applies a change.

**Noctalia settings (declarative vs runtime):** `programs.noctalia.settings` writes the declarative `~/.config/noctalia/config.toml` (persisted). The Noctalia GUI writes to `~/.local/state/noctalia/settings.toml`, which is **not** persisted (wiped on reboot). GUI changes must be ported back into `modules/desktop/noctalia.nix` to survive. The greeter is the same story in reverse: its `greeter.toml` is a tmpfiles symlink into the store, rebuilt every boot from `programs.noctalia-greeter.settings`, so its mutable `sync.toml` is ignored — configure the greeter declaratively, not via shell "greeter sync".

**Noctalia plugins:** Install by symlinking the plugin directory into `~/.local/share/noctalia/plugins/<name>` with `xdg.dataFile` — that path is always scanned as the last (highest-precedence) plugin root, so no source config is needed and the scan follows symlinks. The plugin repo is pinned as a `flake = false` input (`noctalia-plugins` → `noctalia-dev/community-plugins`). Three separate keys, all in `desktop/noctalia.nix`: `settings.plugins.enabled` (discovery alone does **not** load a plugin), `settings.plugin_settings."<author>/<plugin>"` for plugin-level settings, and `settings.widget.<name>` for per-instance ones — a named instance carrying `type = "<author>/<plugin>:<entry>"`, with `<name>` in the `bar.*.{start,center,end}` zone (Noctalia resolves unknown widget types through the plugin registry, so the full entry id also works as the instance name with no `type` key). `settings.plugins.source = [ ]` is deliberate: with the key absent Noctalia seeds two built-in *git* sources and re-clones both (~16MB) into non-persisted `~/.local/state/noctalia` on **every boot**; an explicit empty array suppresses that (it probes the raw table for the array, so `[]` counts as configured and a missing key does not). The trade is an empty in-shell plugin browser. Note `programs.noctalia.validateConfig` runs in a sandbox with no plugin dir, so every plugin key emits an "unrecognized widget type" / "no loaded plugin with this id" **warning** during the build — warnings don't fail validation, so leave `validateConfig` on.

**Session variables:** `home.sessionVariables` is written to `hm-session-vars.sh` (a POSIX script) and, for a subset, `~/.config/environment.d/10-home-manager.conf`. nushell is the login shell and sources **neither**, so those variables were silently absent from every interactive shell — `EDITOR` stayed at NixOS's `nano` rather than HM's `nvim`. `modules/shell/nushell.nix` bridges them into `programs.nushell.environmentVariables`, skipping values containing `$` (POSIX expansions like `XDG_CONFIG_DIRS`, which nushell would take literally and which it already inherits correctly from the session). Declare user variables in `home.sessionVariables` and the bridge picks them up; variables a *GUI* app needs still have to reach the systemd user manager separately.

**Editor:** Nixvim with LSP servers for Nix (nixd), Lua, Rust, TypeScript, Python, and Bash. No colorscheme is configured — nvim uses its default (`shell/editor.nix`).
